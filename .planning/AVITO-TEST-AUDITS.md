## 2. Вход / auth

Если тест пойдёт на preview с этим env — ВСЕ тестировщики окажутся одним пользователем: общие сессии уроков, перемешанные транскрипты, «пройдено» друг за друга. Статистику по людям собрать будет невозможно.

Многопользовательность как таковая — ок (JWT-cookie, данные всюду фильтруются по `userId`).

**Доделать:** верифицировать домен в Resend + сменить `from`; решить процесс онбординга (оператор руками гоняет `admin:create-user` на каждого тестера — приемлемо для 5-10 человек, но нужен раннбук) ЛИБО быстрая форма самозаписи; снять `KLASSIO_DEV_USER_ID` с тестового окружения.

## 1. Старт урока

**СТАТУС: частично** — happy-path продуман, деградации нет.

Как устроено:
- Ребёнок видит центральную кнопку «Начать урок», инжектится самим канвасом и скрыта, пока React не подключил `onStart` — мёртвого клика нет (`public/tutor/anya.html:2599-2611`, `components/tutor/tutor-lesson.tsx:583`).
- Клик → `getUserMedia({audio:true})` только ради permission, треки сразу гасятся (`tutor-lesson.tsx:471-480`). Ошибки различаются: «Разреши доступ к микрофону в браузере» / «Микрофон не найден» / generic (`:472-476`), показываются красным тостом (`:668-672`).
- Оптимистичное «Подключение…» до резолва mic+signed-url (`:602-606`).

Сырость:
- **Проверки звука НЕТ вообще**: ни индикатора уровня микрофона, ни теста динамиков, ни «скажи "привет", я проверю, что слышу». Если мик выдаёт тишину (аппаратный mute, не тот девайс выбран) — Аня поздоровается и будет вечно ждать; ребёнок и родитель не поймут, кто виноват.

- Если iframe-канвас не поднял `__klassioEngine` — 60 секунд поллинга и `console.warn` (`tutor-lesson.tsx:584-587`): ребёнок видит красивый фон **без кнопки старта и без сообщения об ошибке**.
- `conversation.startSession(...)` **не awaited** (`tutor-lesson.tsx:499`) — асинхронная ошибка SDK минует `catch` (`:511-514`); сброс `starting` держится только на том, что SDK успеет перейти в `connecting`. В Sber-клоне это исправлено (`tutor-lesson-ru.tsx:419` — с `await`).

Доделать до теста: pre-flight «звук+мик» экран (уровень микрофона + «слышишь меня? нажми да»), человеческая инструкция при NotAllowedError, видимая ошибка при не-поднявшемся канвасе, `await` на startSession.

А тебя как зовут?»` (`:506-509`) — Аня посреди урока заново спрашивает имя и начинает разминку-знакомство. Контекст LLM потерян. ## 2. 11labs: деньги и лимиты

## 3. VPS-прокси: единая точка отказа

**СТАТУС: ЧАСТИЧНО — живой и самоперезапускающийся, но SPOF без наблюдения.**

- **SPOF — да, тройной**: один VPS несёт ОБА голосовых стека (11labs-прокси и Sber-оркестратор), плюс зависимость от **nip.io** (сторонний wildcard-DNS; ляжет nip.io — лягут оба стека при живом сервере) и одного LE-сертификата.
- **Healthcheck**: есть эндпоинты (`voice-proxy/index.mjs:58-62`, `sber-tutor/index.mjs:456-459`), оба отвечают. **Внешнего мониторинга/алертинга нет никакого** — 14 дней аптайма означает лишь, что никто не заметил бы падения, кроме ребёнка на уроке.
- **Перезапуск**: systemd `Restart=always, RestartSec=5s, StartLimitBurst=5/60s`, MemoryMax 512M/768M (`infra/h2nexus/systemd/*.service`) — есть. Но **рестарт = мгновенная смерть всех идущих уроков**: состояние Sber-сессий в памяти процесса (`index.mjs:478`), а в клиентских хуках **нет ни одного упоминания reconnect/retry** (grep по `components/tutor` пуст). Ребёнок получит молчащую Аню без объяснений.
- **5–10 одновременных**: voice-proxy — тупой pipe, выдержит десятки. Sber-оркестратор — один Node-процесс, `maxSockets: 32` (`index.mjs:83`), память на сессию умеренная; узкое место не VPS, а **лимиты конкурентности GigaChat/SaluteSpeech на PERS-ключах** (не проверены). Отдельно: `ensureTokens()` без single-flight — при одновременном старте сессий возможен дубль-рефреш OAuth (безвредно, но шумно).

## 4. Секреты / безопасность

**СТАТУС: ЕСТЬ (для масштаба «30 тестеров») с двумя оговорками.**

Хорошее:
- Ключи на клиент не текут: grep `NEXT_PUBLIC_` — только BUILD_SHA/BRANCH; `ELEVENLABS_API_KEY` живёт в серверном модуле (`lib/elevenlabs/get-signed-url.ts`), в браузер уходит только обёрнутый signed URL.
- Оба WS-пути подписаны: HMAC-SHA256 + TTL 5 мин + constant-time compare (`voice-proxy/index.mjs:40-48,90-101`; `sber-tutor/index.mjs:449-472`); прокси дополнительно whitelist'ит upstream `wss://api.elevenlabs.io/` (`proxy-url.ts:63`).
- Все `/api/tutor/*` — auth-first + ownership-чек сессии (`session/route.ts:25-26`, `signed-url/route.ts:35-36`, `transcript/route.ts:38-39`). Регистрация закрыта whitelist'ом `allowed_email` (`lib/db/schema.ts:76-77`).

Оговорки:
- **Rate-limit отсутствует полностью** (grep по `rate.?limit|upstash` — пусто). Пока превью за Vercel SSO — неважно; **как только SSO снимут для тестеров** (а снять придётся, см. п.1), останется только email-whitelist. Для 30 тестеров приемлемо, «нагадить, зная URL», сможет лишь залогиненный whitelist-юзер (спам минтинга signed-url = минуты 11labs).
- **`KLASSIO_DEV_USER_ID` — полный обход аутентификации** (`lib/tutor/http.ts:17-21`): любой запрос без сессии становится юзером Кратова. Сейчас только в `.env.local`, но код дырки не закоммичен и без guard'а — одна ошибочная переменная на Vercel = публичный вход без пароля. Нужен предохранитель `if (process.env.VERCEL_ENV === 'production') ignore`.
- Мелочь: `rejectUnauthorized: false` к Sber (`sber-tutor/index.mjs:83`) — осознанный компромисс из-за русских CA, MITM-поверхность ограничена плечом VPS→Sber; Sber-токен `sid:t:s` реплеится 5 минут (несколько параллельных коннектов на один sid) — жжёт токены GigaChat, не данные.

## 5. Наблюдаемость

**СТАТУС: ЧАСТИЧНО — «что говорила Аня» восстановим, «почему зависло у тестера №7» — нет.**

- **VPS**: journald с идентификаторами `klassio-voice-proxy` / `klassio-sber-tutor`; sber-логи содержат `sid` (первые 8 символов) + пер-turn латентность (коммит `b6f846a`), voice-proxy — только IP и хвост upstream-URL, **без связи с userId/sessionId**.
- **Vercel**: function-логи (`console.error` в каждой ручке) — эфемерные, log drain не настроен; через сутки расследовать нечего.
- **Клиент**: НИЧЕГО — ни Sentry, ни отправки JS-ошибок, ни network-телеметрии. Именно клиент (мик, автоплей аудио, WS-разрыв) — самое вероятное место «зависло».
- **Данные**: `lesson_transcript` (батч-флаш, `transcript/route.ts`), `progress_event`, `tutor_session` — по контенту урока постмортем возможен. По техническому сбою — только если совпадёт время в journald.
- Вердикт по сценарию «у тестера №7 зависло»: найдём его сессию и последнюю реплику, **не найдём** причину (клиентская ошибка? разрыв WS? Cloudflare? лимит Sber?).

## 1. Рекрутинг с Авито — СТАТУС: НЕТ

**Доказательства:**

**Как это реально делают в 2026 (RU):**

Важный нюанс, который в vision-доках не учтён: **честное объявление «платим за участие в тесте» на Авито проходит плохо**. В разделе «Вакансии» модерация Авито склонна блокировать «участие в опросах/тестах за деньги» как скам-паттерн (категория «заработок на опросах» токсична), а фейковые вакансии — прямое нарушение правил с риском блокировки профиля ([эксперимент harant.ru](https://harant.ru/questions/q-68631/), [правила Авито, vc.ru](https://vc.ru/marketing/2102752-pravila-razmeshheniya-ob-yavleniy-na-avito)). Рабочие стратегии — две, и они разные по цели:

- **Стратегия А — «Авито Услуги → Репетиторы» (рекомендую как основную).** Размещаешь объявление *репетитора* с бесплатным/дешёвым пробным уроком. Это одновременно (а) законный формат для площадки, (б) валидация именно того канала, который заложен в видении продукта (`.planning/intel/requirements.md:15` — «объявление обычного репетитора, AI прячется внутри»), (в) даёт «незнакомых людей с улицы», а не профессиональных респондентов. Этическая развилка: НЕ прятать ИИ до созвона нельзя — родитель должен узнать про ИИ и запись **до** урока (на скрининг-созвоне), иначе согласие 152-ФЗ невалидно и отзывы будут отравлены обманом.
- **Стратегия Б — честный рекрут «тест продукта за вознаграждение»** — но не на Авито, а в телеграм-чатах рекрутинга респондентов («Ищу респондентов», «Рекрутинг респондентов UX»), мамских районных чатах и VK-группах. Это стандартная практика при самостоятельном рекруте ([UsabilityLab о критериях отбора](https://usabilitylab.ru/blog/poisk-respondentov-dlya-yuzabiliti-testirovaniya-chast-1-kriterii-otbora/)). На Авито вариант Б возможен только в «Услугах» с формулировкой без слова «заработок» (см. черновик ниже) — и надо быть готовым к отклонению модерацией.

**Сколько платят (вилка 2026):** базовая ставка взрослому респонденту за 30–60 мин — **1000–1500 ₽** ([vc.ru про экономику рекрутинга](https://vc.ru/marketing/74594-skolko-na-samom-dele-stoyat-respondenty-rasschityvaem-ekonomiku-rekrutinga-dlya-issledovanii), [обзор платных исследований](https://vc.ru/services/1852273-oprosy-za-dengi-i-platnye-issledovaniya-gde-iskat-i-skolko-platyat)). ## 3. Протокол сессии — СТАТУС: НЕТ

**Доказательства:** ни в `.planning/`, ни в `scripts/` нет ни сценария модератора, ни чеклиста. `SESSION-2026-06-19-EDU-PLATFORM-TEST-LIVE.md` — про технический стенд, не про людей.

**Что выбрать: модерируемый, удалённый, с двумя устройствами.** Немодерируемый («сам дома») для голосового урока с ребёнком на этой стадии противопоказан: (а) первый же технический затык (микрофон не дался, латентность, echo) убьёт сессию, и ты об этом даже не узнаешь; (б) главный сигнал — невербалика ребёнка (скука, растерянность, восторг), её без наблюдения не собрать. Стандарт: модерируемый качественный тест, наблюдение + «мысли вслух» ([Контур.Гайды](https://guides.kontur.ru/principles/user-research/choosingresearch/), [гайд UsabilityLab 2026](https://usabilitylab.ru/blog/kak-provesti-yuzabiliti-testirovanie-poshagovyj-gajd/)). С детьми 7–11 классический think-aloud работает плохо (стесняются, замолкают) — вместо него наблюдение + короткие вопросы в паузах, и чуть больше дружелюбия/похвалы, чем со взрослыми, но без наводок ([NN/g: Usability Testing with Minors](https://www.nngroup.com/articles/usability-testing-minors/), [UX Design for Children, NN/g](https://www.nngroup.com/reports/children-on-the-web/)). Для 9–12 лет индивидуальные сессии ок (пары нужны только 6–8-леткам).

**Ключевая техническая развилка протокола (специфика голосового урока):** урок занимает микрофон устройства ребёнка — созвон с модератором на том же устройстве невозможен. Схема: **урок на ноутбуке ребёнка (динамики, НЕ наушники) + созвон на телефоне родителя** (камера направлена на ребёнка и экран, микрофон телефона ловит и Аню, и ребёнка). Наушники — только fallback, если динамики дают ложные перебивания (echo cancellation браузера обычно справляется). Созвон — **Яндекс Телемост или Google Meet**: звонки в Telegram/WhatsApp в РФ деградированы с 2025, на них полагаться нельзя.

**Скелет сессии (60–75 мин):** 10 мин тех-чек с родителем (открыть ссылку урока, дать микрофон, проверить звук) → 5 мин знакомство с ребёнком (модератор: «Аня — компьютерная учительница, она только учится, ты помогаешь нам её проверить — если что-то не получится, это её ошибка, не твоя») → 25–30 мин урок, модератор **молчит** (не подсказывать: как отвечать Ане, что нажимать, «скажи погромче»; вмешиваться только при полном зависании >60 сек) → 10 мин беседа с ребёнком → 10–15 мин опрос родителя (ребёнка отпустить) → оплата.

**Сколько сессий:** 5–6 на итерацию — после 5 качественных сессий новые проблемы почти не появляются ([UsabilityLab: сколько нужно респондентов](https://usabilitylab.ru/blog/usability-testing-respondents/), [askusers](https://askusers.ru/blog/ux-mify/skolko-nuzhno-respondentov-dlya-testa/)). Рекрутить 8 (2 отвалятся). Первую сессию — пилот на «своём» ребёнке (не с Авито) для обкатки протокола.

**Что доделать:** чеклист (ниже), тестовый прогон схемы «динамики+телефон родителя» на предмет echo/перебиваний ДО первого чужого ребёнка, страница-«приёмная» с кнопкой проверки микрофона.

**За 24 ч:** □ напоминание □ согласие отправлено → **подписано и получено** (без него сессии нет) □ ссылка урока протестирована мной сегодня (11labs-прокси жив, `?stack=` fallback жив) □ ссылка на Телемост создана.

**Тех-чек (10 мин, с родителем):** □ созвон на телефоне родителя, камера видит ребёнка+экран □ на записи проговорено «идёт запись, согласие подписано — подтверждаете?» □ урок открыт в Chrome □ микрофон разрешён □ звук через динамики □ Аня слышит тестовую фразу ребёнка □ телефон родителя на зарядке/не упадёт.

**Установка ребёнку (дословно):** «Это Аня, компьютерная учительница. Она ещё учится, и ты сегодня — её проверяющий. Если она что-то не поймёт или ошибётся — это её ошибка, а не твоя, нам как раз важно такое найти. Разговаривай с ней как с обычной учительницей.»

**Во время урока (молчать; тикать счётчики):** □ «не поняла»/переспросы Ани: ___ □ ложные перебивания: ___ □ вопросы ребёнка к родителю: ___ □ зависания >10 сек: ___ □ тех-фейлы: ___ □ на какой доске/минуте потерял интерес: ___ □ момент максимальной вовлечённости: ___. **Вмешательство** только при зависании >60 сек: сначала «спроси Аню ещё раз», перезагрузка страницы — крайняя мера.

**После:** □ 5 вопросов ребёнку (см. п.4) □ ребёнка отпустить □ опросник родителя □ перевод по СБП, подтверждение на записи □ в тот же вечер: выгрузить транскрипт, заполнить лист дебрифа, 3 главных инсайта.

## Г. Опросник родителя (10–15 мин, устно на созвоне)

1. Что вы увидели глазами: чем это занятие отличалось от обычного занятия с репетитором/в школе? *(открытый, первым — пока не «якорь»)*
2. Был ли момент, когда вы напряглись или захотели вмешаться? Какой?
3. Ребёнок понял материал, как вам кажется? Что бы он смог пересказать?
4. По 10-балльной шкале: насколько вероятно, что порекомендуете такие занятия знакомым родителям? Почему именно столько? *(NPS + «почему» важнее цифры)*
5. Если бы такие уроки исчезли и больше нельзя было бы заниматься — насколько бы вы расстроились: очень / немного / никак? *(PMF Шона Эллиса)*
6. Цена: какая цена за месяц занятий (8 уроков) была бы для вас **приемлемой**? А какая — **уже слишком дорогой**? И прямо: за 1490 ₽/мес — оформили бы подписку сегодня? *(Ван Вестендорп-лайт + прямой WTP; фиксировать и цифры, и колебания)*
7. Что должно измениться, чтобы вы доверили Ане регулярные занятия без вашего присутствия?

## Д. Скелет согласия родителя (на вычитку юристу)

> **Согласие законного представителя на обработку персональных данных несовершеннолетнего**
> Я, ФИО, паспорт …, являясь законным представителем (ФИО ребёнка, дата рождения), даю согласие [ФИО/наименование оператора, адрес] на обработку ПДн ребёнка: имя, возраст, класс; **аудиозапись голоса и её текстовая расшифровка (транскрипт) учебного занятия; видеозапись экрана и видеосвязи во время занятия**. Цели: проведение исследовательского тестирования образовательного сервиса, анализ и улучшение качества сервиса. Действия: сбор, запись, систематизация, хранение, анализ, обезличивание, удаление; **обработка с использованием автоматизированных сервисов распознавания и синтеза речи**. Данные не передаются третьим лицам для маркетинга. Срок хранения записей — 6 месяцев, далее уничтожение. Согласие действует 1 год и может быть отозвано письменно по адресу … Дата, подпись.
> *(Если ребёнку 14+ — дублирующее согласие от самого ребёнка.)*

# ЧТО ДОДЕЛАТЬ ДО ПЕРВОГО ЧЕЛОВЕКА С АВИТО (по приоритету)

1. **[Блокер, ~1 день]** Согласие 152-ФЗ (скелет выше → юрист) + страница `/privacy` на сайте + подать уведомление РКН.
2. **[Блокер, ~0.5 дня]** Тех-прогон протокола «динамики + телефон родителя» на своём ребёнке: не рвут ли динамики VAD/перебивания Ани. Если рвут — протокол меняется на наушники+пересказ, это надо знать заранее.
3. **[~0.5 дня]** Объявление (вариант А в Авито Услуги + вариант Б в 2–3 TG-чата), скрининг-скрипт, отдельный TG для заявок.
4. **[~2 часа]** Скрипт метрик из `lesson_transcript` + Яндекс.Метрика на роут урока.
5. **[~1 час]** Распечатать/завести чеклист сессии и лист дебрифа; создать слоты в календаре; заготовить fallback-ссылку `?stack=`.
6. Пилотная сессия №0 на знакомом ребёнке → правка протокола → 5–6 сессий с Авито → итерация.
