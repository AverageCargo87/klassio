# Klassio Admin Guide

> This guide is for developers managing test users and lessons. No web UI — commands run locally against the live Neon DB.

## Quickstart (30 seconds)

Create a test child and schedule a lesson:

```bash
# 1. Create a test child (also whitelists the email for login)
npm run admin:create-user -- --email kid@example.ru --child-name "Маша" --child-age 10

# 2. Schedule a lesson for them
npm run admin:create-lesson -- --email kid@example.ru --topic "Сложение в столбик" --date 2026-06-01 --time 16:00

# 3. Verify
npm run admin:list-users
npm run admin:list-lessons
```

Then go to /login, enter kid@example.ru, click the magic link → the child sees the lesson in their schedule.

## Prerequisites

- `.env.local` with `DATABASE_URL_DIRECT` (non-pooler Neon connection string)
- Node.js ≥ 20 installed (`node --version`)
- Project dependencies installed (`npm install`)

## Command Reference

### `admin:create-user`

Creates or updates a user and whitelists their email for magic-link login.

```bash
npm run admin:create-user -- --email <email> [--child-name <name>] [--child-age <age>]
```

| Flag | Required | Default | Description |
|------|----------|---------|-------------|
| `--email` | Yes | — | Parent/child email for login |
| `--child-name` | No | "Ребёнок" | Display name of the child |
| `--child-age` | No | 10 | Child's age (integer) |

**Idempotent:** re-running updates child_name and child_age without creating duplicates.

Example:
```bash
npm run admin:create-user -- --email masha@example.ru --child-name "Маша" --child-age 11
# ✓ Whitelisted email masha@example.ru
# ✓ Created/updated user (email: masha@example.ru, child: Маша, age: 11)
# ✓ Magic link: visit /login and enter this email to receive a login link
```

### `admin:create-lesson`

Creates a lesson bound to an existing user.

```bash
npm run admin:create-lesson -- --email <email> --date <YYYY-MM-DD> [--time <HH:mm>] [--topic <topic>] [--duration <minutes>] [--trainer <path>]
```

| Flag | Required | Default | Description |
|------|----------|---------|-------------|
| `--email` | Yes | — | Email of the user to attach the lesson to |
| `--date` | Yes | — | Lesson date (YYYY-MM-DD) |
| `--time` | No | "10:00" | Lesson start time (HH:mm, local time) |
| `--topic` | No | "Тестовый урок" | Lesson topic (free text) |
| `--duration` | No | 45 | Duration in minutes |
| `--trainer` | No | — | Path to HTML trainer file (for Phase 7) |

**Note:** Each run creates a new lesson (lessons are not unique on any natural key). Re-running creates a duplicate — check with `admin:list-lessons` first.

Example:
```bash
npm run admin:create-lesson -- --email masha@example.ru --date 2026-06-15 --time 16:00 --topic "Дроби — введение"
# ✓ Lesson created (id: abc12345-...)
#   Topic: Дроби — введение
#   Scheduled: Вс 15 июня 2026 в 16:00 (local time)
#   User: masha@example.ru
```

### `admin:list-users`

Prints all users in the database.

```bash
npm run admin:list-users
```

Output columns: ID (truncated) | Email | Child | Age | Created | Last Login

### `admin:list-lessons`

Prints all lessons with the associated user email.

```bash
npm run admin:list-lessons
```

Output columns: ID (truncated) | Email | Topic | Scheduled | Duration | Status

## FAQ

**Q: How do I delete a user?**
Connect to the database directly (Neon Console → SQL Editor) and run:
```sql
DELETE FROM "user" WHERE email = 'kid@example.ru';
-- Cascade deletes their lessons, sessions, accounts automatically
```

**Q: How do I change a lesson's date/time?**
Delete the lesson and re-create it:
```sql
DELETE FROM lesson WHERE id = '<lesson-uuid>';
```
Then run `npm run admin:create-lesson` again.

**Q: How do I cancel a lesson?**
Update the status directly in Neon Console:
```sql
UPDATE lesson SET status = 'cancelled' WHERE id = '<lesson-uuid>';
```
The lesson will then appear in the "Прошедшие уроки" section with status "Отменён".

**Q: The email whitelist — what is it?**
Klassio uses an invite-only email whitelist (`allowed_email` table). Only emails in this list can log in via magic link. `admin:create-user` automatically adds the email to the whitelist. To add an email without creating a user:
```sql
INSERT INTO allowed_email (email, notes) VALUES ('new@example.ru', 'manual add') ON CONFLICT DO NOTHING;
```

## Troubleshooting

**Error: `DATABASE_URL_DIRECT is required`**
The `.env.local` file is missing or the variable is not set. Copy `.env.example` and fill in your Neon direct connection string (from Neon Console → Connection Details → Direct connection).

**Error: `User not found for email ...`**
Run `admin:create-user` for the email first, then retry `admin:create-lesson`.

**Error: ECONNRESET during lesson creation**
This is a known Neon Free tier quirk — the write likely succeeded despite the error. Run `admin:list-lessons` to verify the lesson was created. If not, re-run `admin:create-lesson`.

**Magic link not arriving in email**
In development, magic links are written to a temp file (not sent via Resend) when `AUTH_RESEND_OVERRIDE_FILE` env var is set. For the production deployment, verify that the sending domain is verified in Resend (Dashboard → Domains). See `.planning/MANUAL-ACTIONS.md` for post-deploy email deliverability steps.

import { test, expect } from '@playwright/test'
import {
  seedTestUser,
  resetTestDb,
  makeTestEmail,
  readMagicLinkFor,
  clearMagicLinkFile,
} from './fixtures/db-setup'
// Import pgQuery helper directly for inserting a past lesson
// Note: pgQuery is not exported from db-setup.ts — replicate the pattern inline or
// use the pg Client directly for the past lesson INSERT.
import { config as loadDotenv } from 'dotenv'
import { resolve } from 'path'
import pkg from 'pg'

const { Client } = pkg

loadDotenv({ path: resolve(process.cwd(), '.env.local') })

async function insertPastLesson(userId: string, topic: string): Promise<string> {
  const yesterday = new Date(Date.now() - 24 * 60 * 60 * 1000)
  const client = new Client({
    connectionString: process.env.DATABASE_URL_DIRECT,
    ssl: { rejectUnauthorized: false },
  })
  await client.connect()
  try {
    const result = await client.query<{ id: string }>(
      `INSERT INTO lesson (user_id, scheduled_at, topic, duration_min, status)
       VALUES ($1, $2, $3, 45, 'completed') RETURNING id`,
      [userId, yesterday.toISOString(), topic]
    )
    return result.rows[0].id
  } finally {
    await client.end()
  }
}

test.describe('Schedule grouping UI', () => {
  const email = makeTestEmail('schedule-grouping')
  let userId: string

  test.beforeAll(async () => {
    const seeded = await seedTestUser(email)
    userId = seeded.userId
    // Add a past lesson so the past section has content
    await insertPastLesson(userId, 'E2E прошедший урок')
  })

  test.afterAll(async () => {
    await resetTestDb()
  })

  async function loginAndNavigateToLessons(page: import('@playwright/test').Page, baseURL: string) {
    await page.goto('/login')
    // Use the same selector as login-happy-path.spec.ts — read that file first to confirm
    await page.fill('input[type="email"]', email)
    clearMagicLinkFile()
    await page.click('button[type="submit"]')

    // Poll for magic link (same pattern as login-happy-path.spec.ts)
    let magicLink: string | null = null
    for (let i = 0; i < 20; i++) {
      await page.waitForTimeout(500)
      magicLink = await readMagicLinkFor(email, baseURL)
      if (magicLink) break
    }
    expect(magicLink).toBeTruthy()
    await page.goto(magicLink!)
    await page.waitForURL('**/lessons')
  }

  test('shows Расписание heading and at least one week bucket', async ({ page, baseURL }) => {
    await loginAndNavigateToLessons(page, baseURL ?? 'http://localhost:3000')
    await expect(page.getByRole('heading', { level: 1 })).toContainText('Расписание')
    // seedTestUser creates 1 lesson 1 hour from now (this week)
    await expect(page.getByRole('heading', { level: 2 }).first()).toContainText('Эта неделя')
  })

  test('past lessons section is collapsed by default', async ({ page, baseURL }) => {
    await loginAndNavigateToLessons(page, baseURL ?? 'http://localhost:3000')
    // The collapsible content should not be visible initially
    await expect(page.getByText('E2E прошедший урок')).not.toBeVisible()
    // But the trigger button should be visible
    await expect(page.getByRole('button', { name: /Прошедшие уроки/i })).toBeVisible()
  })

  test('expanding past lessons section reveals past lesson cards', async ({ page, baseURL }) => {
    await loginAndNavigateToLessons(page, baseURL ?? 'http://localhost:3000')
    // Click the collapsible trigger
    await page.getByRole('button', { name: /Прошедшие уроки/i }).click()
    // Past lesson card should now be visible
    await expect(page.getByText('E2E прошедший урок')).toBeVisible()
    // Status label should be visible
    await expect(page.getByText('Проведён')).toBeVisible()
    // Recording placeholder should be visible
    await expect(page.getByText(/Phase 10|запись|появится/i)).toBeVisible()
  })

  test('lesson card shows smart-relative date (not raw ISO)', async ({ page, baseURL }) => {
    await loginAndNavigateToLessons(page, baseURL ?? 'http://localhost:3000')
    // The upcoming lesson (1 hour from now) should show "Сегодня в" (today)
    await expect(page.getByText(/Сегодня в/)).toBeVisible()
  })

  test('empty upcoming state shows correct message when no upcoming lessons', async ({ page }) => {
    // Create a fresh user with NO upcoming lessons — seedTestUser always creates 1.
    // Instead, use a separate email that we seed manually without a lesson.
    const emptyEmail = makeTestEmail('schedule-empty')
    const client = new Client({
      connectionString: process.env.DATABASE_URL_DIRECT,
      ssl: { rejectUnauthorized: false },
    })
    await client.connect()
    try {
      await client.query(
        'INSERT INTO allowed_email (email, notes) VALUES ($1, $2) ON CONFLICT (email) DO NOTHING',
        [emptyEmail, 'e2e empty-state test']
      )
      await client.query(
        `INSERT INTO "user" (id, email, child_name, child_age) VALUES (gen_random_uuid()::text, $1, 'E2E Empty', 10) ON CONFLICT (email) DO NOTHING`,
        [emptyEmail]
      )
    } finally {
      await client.end()
    }

    await page.goto('/login')
    await page.fill('input[type="email"]', emptyEmail)
    clearMagicLinkFile()
    await page.click('button[type="submit"]')
    let magicLink: string | null = null
    for (let i = 0; i < 20; i++) {
      await page.waitForTimeout(500)
      magicLink = await readMagicLinkFor(emptyEmail, 'http://localhost:3000')
      if (magicLink) break
    }
    if (!magicLink) {
      test.skip() // skip if magic link not received (CI environment quirk)
      return
    }
    await page.goto(magicLink)
    await page.waitForURL('**/lessons')
    await expect(page.getByText(/4 недели.*запланировано|свяжитесь с репетитором/i)).toBeVisible()
    // Cleanup
    const cleanupClient = new Client({ connectionString: process.env.DATABASE_URL_DIRECT, ssl: { rejectUnauthorized: false } })
    await cleanupClient.connect()
    await cleanupClient.query('DELETE FROM "user" WHERE email = $1', [emptyEmail])
    await cleanupClient.query('DELETE FROM allowed_email WHERE email = $1', [emptyEmail])
    await cleanupClient.end()
  })
})
