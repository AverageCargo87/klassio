## 1. Что купить

**Любой российский VPS самого младшего тарифа.** Требования смешные, потому что урок —
это один процесс node без единой зависимости и 29 МБ файлов.

| параметр | нужно | комментарий |
|---|---|---|
| vCPU | 1 | нагрузка = отдать файлы и сходить в Яндекс |
| RAM | 1 ГБ | процесс держит ~80 МБ |
| диск | 10 ГБ | пакет 29 МБ + система |
| ОС | Ubuntu 22.04 или Debian 12 | |
| цена | 200–400 ₽/мес | Timeweb Cloud · Selectel · Reg.ru Cloud · Beget |

**Домен покупать не нужно.** Работает трюк `nip.io`: адрес `https://<ваш-ip>.nip.io`
резолвится сам, и Let's Encrypt на него выдаёт сертификат. Мы так уже делали с боевым сайтом.

⚠️ **Регион — Россия.** Смысл переезда в том, что голос (синтез и распознавание Яндекса)
лежит в критическом пути: на каждую реплику урок ходит в Яндекс. Из Европы это лишние
десятки миллисекунд на каждой фразе.

## 2. Развернуть (один раз, ~15 минут)

Ниже `IP` — адрес нового сервера. Всё выполняется на нём под root.

**2.1. Node 20 и nginx**

```bash
curl -fsSL https://deb.nodesource.com/setup_20.x | bash - && apt install -y nodejs nginx certbot python3-certbot-nginx apache2-utils
```

⚠️ Node не ниже 18: сервер ходит в Яндекс встроенным `fetch`, в 16-м его нет.

**2.2. Положить пакет.** На своей машине:

```bash
node scripts/pack-lab.mjs
```

Получится `.tmp/lab-deploy.tar.gz` (~20 МБ). Отправить и распаковать:

```bash
scp .tmp/lab-deploy.tar.gz root@IP:/tmp/ && ssh root@IP "mkdir -p /opt/klassio-lab && tar -xzf /tmp/lab-deploy.tar.gz -C /opt/klassio-lab"
```

**2.3. Ключи Яндекса.** На сервере создать `/opt/klassio-lab/.env`:

```bash
printf 'YANDEX_API_KEY=%s\nYANDEX_FOLDER_ID=%s\n' 'КЛЮЧ' 'ПАПКА' > /opt/klassio-lab/.env && chmod 600 /opt/klassio-lab/.env
```

Значения — те же, что в локальном `Klassio/.env.local`.

**2.4. Служба systemd** — `/etc/systemd/system/klassio-lab.service`:

```ini
[Unit]
Description=Klassio lab (витрина сборок урока)
After=network.target

[Service]
WorkingDirectory=/opt/klassio-lab
EnvironmentFile=/opt/klassio-lab/.env
Environment=PORT=8781
ExecStart=/usr/bin/node scripts/yandex-test-server.mjs
Restart=always
RestartSec=3

[Install]
WantedBy=multi-user.target
```

```bash
systemctl daemon-reload && systemctl enable --now klassio-lab && systemctl status klassio-lab --no-pager
```

⚠️ `Restart=always` здесь не роскошь: стенд за время работы дважды падал сам.

**2.5. Пароль.** Два повода, оба серьёзные: страницы — рендер учебника Мединского под
копирайтом, и открытый адрес означает, что чужие люди жгут наш ключ Яндекса.

```bash
htpasswd -bc /etc/nginx/.htpasswd shef ПРИДУМАТЬ_ПАРОЛЬ
```

**2.6. nginx** — `/etc/nginx/sites-available/klassio-lab`:

```nginx
server {
  listen 80;
  server_name IP.nip.io;
  auth_basic "Klassio";
  auth_basic_user_file /etc/nginx/.htpasswd;
  client_max_body_size 20m;
  location = / { return 302 /lab; }
  location / {
    proxy_pass http://127.0.0.1:8781;
    proxy_http_version 1.1;
    proxy_set_header Upgrade $http_upgrade;
    proxy_set_header Connection "upgrade";
    proxy_read_timeout 300s;
  }
}
```

```bash
ln -s /etc/nginx/sites-available/klassio-lab /etc/nginx/sites-enabled/ && nginx -t && systemctl reload nginx && certbot --nginx -d IP.nip.io
```

**2.7. Проверить.** Открыть `https://IP.nip.io` → должно спросить пароль → витрина с тремя
сборками. Нажать «пройти урок» в каждой.

## 3. Как выкатывать правки и как откатываться (с 11.08)

### Порядок

```bash
node scripts/lab-deploy.mjs --dry                       # что изменится на боевом — и остановиться
node scripts/lab-deploy.mjs -m "поправил разбор ошибки" # выложить
```

Строка `-m` обязательна: она попадает в журнал релизов, и **именно по ней потом выбирают,
куда откатываться**. «Правки» через месяц не значит ничего.

Что делает скрипт по шагам — до боевого дело доходит последним:

1. **зеркалит исходники в `lab/`** — это и есть история под git (см. раздел 6);
2. собирает пакет и **сверяет его с живым релизом файл в файл**, печатая, что именно
   изменится, с пометкой, чьё это: ЧАРЛИ · БРАВО · АЛЬФА · ОБЩЕЕ;
3. делает коммит-снимок и метку `lab-000N` (push не делает — правило проекта);
4. заливает **новой папкой** `releases/000N-…`, переключает ссылку `current`, перезапускает;
5. проверяет живость — 13 адресов, включая все три сборки и их данные;
6. **не встало — сам возвращает прежний релиз** и говорит об этом. Боевой не остаётся сломанным.

⚠️ Отдельная строка в выводе — **«ТРОГАЕМ ОБЩИЕ ДАННЫЕ»**. `blocks.json`, `figures.json`,
`marks.json`, `pages.json`, `map-greece.svg` читают ВСЕ три сборки: правка в ЧАРЛИ через
них меняет и то, что руководитель считает замороженным. Увидел эту строку — либо так и
задумано, либо надо класть копию в `book/vN/`.

### Откат

```bash
node scripts/lab-rollback.mjs                # список: когда, зачем, какие сборки, метка git
node scripts/lab-rollback.mjs --back         # вернуть предыдущий
node scripts/lab-rollback.mjs --to 0003      # вернуть конкретный
node scripts/lab-rollback.mjs --to 0003 --local   # плюс вернуть исходники на рабочей машине
```

Откат — это переставить ссылку `current` и перезапустить службу: **секунды, без выкладки**.
Голая команда без аргументов боевого НЕ трогает: печатает список и готовую строку.

🔑 **Замечания руководителя и ключ Яндекса лежат в `/opt/klassio-lab/shared` и откатом не
стираются.** Иначе первый же откат стёр бы то, ради чего витрина и сделана.

Как это устроено на сервере:

```
/opt/klassio-lab/
  releases/0001-20260811-0746/   ← каждая выкладка отдельной папкой (31 МБ), храним 10
  releases/0002-20260811-1053/      RELEASE.json — зачем, какие версии, метка git
  shared/     .yandex-secret.json · feedback.jsonl   переживают всё
  current -> releases/0002-…        на неё смотрит служба (WorkingDirectory)
```

Переезд на такую раскладку делается один раз: `node scripts/lab-server-init.mjs`
(идемпотентно — повторный запуск ничего не тронет).

### Чейнджлог

Обновляется сам: витрина режет его из `.planning/KNIGA-VERSIONS.md`, который едет в том же
пакете. **Правило: нарезал версию — допиши раздел в журнал**, иначе руководителю нечего
будет читать в «что изменилось».

## 5б. Грабли самой выкладки (куплены 10.08)

- 🔴 **Пути в архиве обязаны повторять локальные один в один.** Сервер читает файлы по
  относительным путям вида `.tmp/sketches/tutor/kniga.html`. Первый пакет разложил их
  «покрасивее», без `.tmp`, — и урок отдавал 500 на каждой странице. Исправлено в упаковщике.
- 🔴 **Стенд падал на старте из-за постороннего файла.** Он читал конфиг эпохи 11labs
  (`.planning/tutor-agent-live-config-*.json`) без всякой защиты, и без него ВЕСЬ процесс
  уходил в цикл перезапусков — то есть урок не открывался из-за файла, к которому он не
  имеет отношения. Теперь чтение обёрнуто, а заглушка полная (включая `tools: []`).
- **`sftp-put.mjs` на этом сервере не заработал** — `fastPut` отвечает «No such file» и на
  большом файле, и на пустом. Разбираться не стали: мы кладём свой SSH-ключ первым же шагом,
  а с ключом штатный `scp` заливает 20 МБ за 10 секунд. Скрипты на `ssh2` остаются для
  h2.nexus, где они работают.
- **Node из репозитория Ubuntu 24.04 — 18.19**, этого достаточно (нужен ≥18 ради встроенного
  `fetch`), и это избавляет от установки сторонних скриптов одной строкой из интернета.

## 6. Контроль версий — как сделано (11.08)

Раньше выкладка распаковывала архив ПОВЕРХ живой папки: прошлого состояния не оставалось
нигде, и откатывать было нечего. Теперь три уровня, и каждый отвечает за своё.

**1. Релизы на сервере — от плохой выкладки.** Раздел 3. Прошлые сборки лежат целиком,
возврат — секунды, замечания при этом не теряются.

**2. Зеркало `lab/` под git — от плохой правки.** Рабочая копия урока лежит в `.tmp/`
(в `.gitignore` вместе с 1.2 ГБ 3D-хлама соседних веток), поэтому истории у неё не было
вообще. Выкладка зеркалит **текст** — 4 страницы сборок и 15 файлов данных, 1.3 МБ — в
папку `lab/` и делает коммит с меткой `lab-000N`. Рендеры страниц учебника, иллюстрации и
3D-модели в git не едут: копирайт и вес; на сервер они по-прежнему приезжают пакетом.
Вернуть исходники на рабочей машине: `node scripts/lab-rollback.mjs --to 000N --local`
(текущая рабочая копия сначала откладывается в `.tmp/lab-before-restore-…`).

⚠️ Зеркало — **не** рабочая копия: правится `.tmp/sketches/tutor/…`, в `lab/` файлы
попадают только выкладкой. Полный перенос урока в `lab/` (чтобы рабочей копией была именно
она) остаётся не сделанным: на него завязаны пути во всех `check-*.mjs`, в упаковщике и в
роутах стенда, и делать это накануне показа руководителю — дурная затея.

**3. Три сборки — три файла, а не три git-ветки.** АЛЬФА `kniga-v1.html` + `book/v1/`,
БРАВО `kniga-v23.html` + `book/v23/`, ЧАРЛИ `kniga.html` + `book/*.json`. Правка в одной не
трогает другие, мержить нечего, все живы одновременно. ⚠️ Кроме ОБЩИХ данных — про них
громкая строка в выводе выкладки (раздел 3).

Чейнджлог по-прежнему из журнала версий: в нём сказано, ЧТО изменилось для ребёнка, а не
какие файлы — для руководителя это единственно полезная форма.
